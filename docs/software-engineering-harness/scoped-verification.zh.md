# 作用域验证

[English](scoped-verification.md) | 中文

本参考文档规定[工程架构](architecture.zh.md)中由仓库定义的验证实例及其验收规则。

## 摘要

验证实例由检查名称和 JSON 作用域组成。名称相同而作用域不同的检查是独立实例。通用运行时将后端、编译器层、硬件和执行模式视为仓库数据。

<a id="instance-identity"></a>
## 实例标识

作用域必须是无损 JSON 对象。标识计算递归排序对象键，并保留数组顺序。实例 ID 是规范化 JSON 对 `[name, scope]` 的 SHA-256。类别描述检查，但不会创建另一实例。重复的名称与作用域组合一律拒绝，包括类别或必需标记不同的组合。

验证配置版本 1 将省略的作用域解析为 `{}`，将省略的适配器选择器解析为检查名称。显式 `adapter` 可独立于实例名称选择仓库命令。标识和路由不使用编译器或后端枚举。

<a id="execution-and-evidence"></a>
## 执行与证据

每个实例独立执行。结果是包含实例、已解析命令和终态结果的有序数组，名称不是映射键。必需及可选实例分别保留状态，包括未配置适配器时的 `NOT_RUN`。命令证据记录实例名称、类别、作用域、已解析的参数与工作目录、有界输出以及工作修订。每轮生成的 UUID 与实例 ID 区分重复执行。

<a id="acceptance"></a>
## 验收

验收重新加载仓库当前验证配置。每个必需实例必须且只能出现一次，并具有相同类别、`required: true`、`PASS` 和非空证据引用。重复验证实例无效，即使它们是可选项或已通过。其他作用域的通过结果不能满足缺失实例。所有验收入口都要求引用的命令证据具有匹配的任务、工作修订、类别和作用域，退出码为零，且没有超时。缺失引用和有歧义的已引用证据 ID 均被拒绝。未被引用的旧 CLI 重复记录既不能满足新验证，也不会阻断它，其字节保持不变。审查批准不能覆盖这些要求。

<a id="persistence"></a>
## 持久化

新验证产物使用版本 3，保留每个检查的类别和作用域，并添加源码与策略的轮次身份。旧 Schema 通过显式版本分派保持可读，但不是回退或降级目标，也不能授权验收。安装后继 Schema 后重新规划和验证。原有任务和证据字节保持不变。[验证策略与源码封存](verification-policy-design.zh.md)定义身份匹配和累积要求。
